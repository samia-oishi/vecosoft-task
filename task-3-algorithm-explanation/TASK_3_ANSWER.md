I used a JavaScript `Map` to build the cache. A cache keeps recently used values ready for reuse. A `Map` stores keys with their values and remembers entry order. The first entry is least recently used; the last is most recently used.

When `get(key)` finds a key, it returns the value and moves that entry to the newest position. If the key is missing, it returns `-1`. When `put(key, value)` adds or updates an entry, it becomes newest. If the cache is over capacity, the oldest entry is removed. For example, with room for A and B, reading A makes B the oldest; adding C then evicts B.

Both operations are average O(1), meaning their work stays roughly constant as the cache grows. Space is O(capacity), because only the allowed number of entries is stored. A limitation is a stream of unique requests with a tiny cache: items may be evicted before reuse, causing frequent misses. AI suggested a map plus linked list; I chose the ordered `Map` alone because it is easier to follow and meets the requirements. I tested reads, updates, misses, and eviction.
